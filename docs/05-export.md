# 数据导出与 CSV 结构

> 对应页面：<https://www.aqistudy.cn/history-data>

图表能看趋势，但对建模、报表填报、课程作业和长期留档来说，需要的是**原始数据本身**。数据导出就是把这层交出来：按城市与时间范围生成 CSV，到「个人中心 → 我的数据」下载。

## 一、先选粒度，再选范围

| 粒度 | 一行代表 | 对应场景 |
| --- | --- | --- |
| **小时** | 一个城市的一个小时 | 过程分析、与逐时气象对齐 |
| **日** | 一个城市的一天 | 日均合规统计、年度对比 |
| **月** | 一个城市的一个月 | 月报、年报、长期趋势 |

粒度决定了「一行是什么」，这一步选错，后面所有统计都会错。比如要算年平均值，用月表按月等权平均与用小时表按小时平均，结果会略有差异——缺测分布不均匀时差异更明显。

## 二、CSV 的结构

导出的文件是**两行表头 + 数据行**：

**第一行是元信息**：数据来源、统计分辨率、有效记录数，以及气象部分的来源与口径。这一行是为了让文件脱离页面后仍然自解释——半年后打开也知道它是按什么口径出的。

**第二行是列名**，大致顺序是：

1. **北京时间** —— 时次，统一按北京时间，不随运行环境变化
2. **城市ID、城市**
3. **七项空气质量指标** —— AQI 与 PM₂.₅、PM₁₀、SO₂、NO₂、CO、O₃，列名带单位
4. **六项气象要素** —— 温度、湿度、风速、降水、能见度、气压，列名带单位
5. **风向**（文本）与**风向角（°，来向）**

几个要点：

- **一列一个指标**，不做行列转置，拿到就能直接进表格软件或 pandas。
- **单位写在列名里**：CO 是 mg/m³，其余浓度是 μg/m³，AQI 无单位。
- **缺测是空值，不是 0**。统计前先按空值处理，否则会把平均值拉低。
- **风向角是来向**，0° 为北风（风从北边来），与气象惯例一致。

## 三、月统计的口径

月表不是把日表数字简单相加，页面对每一列都有明确口径：

- **浓度与气象取有效日的均值**（有缺测的日先按有效字段算，再参与月度平均）；
- **降水取月内日降水的最大值**——月降水量在不同口径下含义不同，这里给的是「月内单日最大降水」，**不能把日降水直接加总当月总量**；
- **风向角取圆周均值**，不是算术平均（350° 与 10° 的平均应该是 0°，不是 180°）。

拿到月表后如果自己再做二次汇总，务必保持同一套口径，否则跨表比较会出现系统性偏差。

## 四、导出是后台任务

点「生成」之后任务在服务端跑，关掉页面、切走设备都不影响。跑完到「个人中心 → 我的数据」下载。

- **任务中心统一下载**：同一批任务的产物都在一个地方，不用回头找链接。
- **失败自动退回额度**：任务失败不扣次数，预留的额度会退回。
- **额度按月计**：每月可导出次数按档位不同，具体数字见官网[会员与权益](https://www.aqistudy.cn/membership)页。

免费账号可以在导出页**查看今日小时数据，但不提供导出**；CSV 导出自体验档起开放。

## 五、一次别取太多

单次查询有点数上限（时间点数 × 城市数），超过会被服务端拒掉。实践上的做法：

- 需要多年逐小时，就按**年**分批取，落地后再合并；
- 需要多城市对比，先确认这些城市是否都在当前档位的「同屏城市数」之内；
- 真正只要趋势时，用日均或月表就够，不必把几百万行小时数据搬下来。

## 六、下载之后

建议在文件里保留第一行的元信息。它记录了这份数据是按什么分辨率、多少条有效记录生成的——回看时这一行比文件名可靠。
